# 单账号分析会话实现说明

## 目标与边界

系统为一个配置账号提供可跨设备恢复的分析会话。所有会话、消息、执行进度、查询结果、上下文记忆和结果行引用均保存于服务端 SQLite；浏览器仅保存界面偏好，**不保存消息内容、查询结果或引用值**。

- 内部用户标识固定为 `single-user`，不提供注册、多用户、组织、共享会话或跨会话检索。
- 账号来自 `APP_AUTH_USERNAME`、`APP_AUTH_PASSWORD`；会话签名密钥和有效期来自 `APP_SESSION_SECRET`、`APP_SESSION_MAX_AGE_SECONDS`。
- 登录成功后服务端下发 `chain_nl2sql_session` Cookie。Cookie 为 `HttpOnly`、`SameSite=Lax`，非 `local` 环境启用 `Secure`。
- 前端路由守卫通过 `GET /api/v1/auth/session` 判断登录状态。401 或会话失效时跳转登录页，登录后回到原路由。

跨设备部署必须由同一 HTTPS 域名的反向代理同时提供前端和 `/api`；不要把 Vite 开发服务或未加密 Cookie 暴露到公网。生产环境启动时拒绝默认会话密钥和默认密码。

## HTTP 接口与查询生命周期

| 接口 | 说明 |
| --- | --- |
| `POST /api/v1/auth/login` | 校验账号密码，设置会话 Cookie，返回登录状态。 |
| `POST /api/v1/auth/logout` | 删除会话 Cookie。 |
| `GET /api/v1/auth/session` | 返回当前 Cookie 的认证状态和用户名。 |
| `GET /api/v1/conversations` | 返回当前账号的会话摘要，按最近更新时间排序。 |
| `POST /api/v1/conversations` | 使用已授权的 `database_id` 创建会话。 |
| `GET /api/v1/conversations/{conversation_id}` | 返回完整消息、已持久化的 SSE 进度及响应快照。 |
| `DELETE /api/v1/conversations/{conversation_id}` | 删除会话及其关联数据。 |
| `POST /api/v1/conversations/{conversation_id}/query` | 在固定数据源内执行会话查询，返回 SSE。 |
| `POST /api/v1/conversations/{conversation_id}/references` | 为结果表的一行创建受控引用。 |
| `POST /api/v1/query` | 保留的无状态兼容查询接口，必须显式传入 `database_id`。 |

会话查询开始时，服务端在同一写事务中创建用户消息、运行中的助手占位消息和 `conversation_turns` 记录。SSE 首先发送 `start`，运行过程中的每个 `progress` 事件会以短事务写入助手消息；`complete` 写入最终 `QueryResponse` 和回合状态，`error` 写入安全失败原因。页面重新打开详情即可恢复已完成结果和中断前的进度。

已存在消息的会话锁定其 `database_id`；前端禁用数据源切换，并在请求运行期间禁用切换和删除操作。

## SQLite 持久化与删除

会话库默认路径为 `data/conversations.sqlite3`，可通过 `CONVERSATION_DATABASE_PATH` 覆盖。数据库启用 WAL、外键和 5 秒 `busy_timeout`，并以 `conversation_meta.schema_version` 记录模式版本。

| 表 | 职责 |
| --- | --- |
| `conversations` | 会话归属、固定数据源、标题和时间。 |
| `conversation_turns` | 一问一答的序号、状态、完成时间和当轮上下文快照。 |
| `conversation_messages` | 用户/助手文本、状态、响应快照和 SSE 进度。 |
| `turn_memories` | 确定性记忆、结果元数据和可选本地向量。 |
| `turn_memory_fts` | 当前会话历史的 SQLite FTS5 检索索引。 |
| `result_references` | 行引用的语义标签和仅服务端可见的参数绑定值。 |

删除 `conversations` 会通过外键级联删除 turn、message、memory 和 reference，并显式清理 FTS 记录。`data/conversations.sqlite3` 及其 `-wal`、`-shm` 文件已在 `.gitignore` 中排除。

应用空闲时可进行 SQLite 在线备份：

```powershell
sqlite3 data/conversations.sqlite3 ".backup 'backups/conversations-YYYYMMDD.sqlite3'"
```

## 上下文记忆

每个成功回合完成时，同步写入确定性记忆：用户问题、意图、涉及表、生成 SQL、结果列和行数。不会依赖异步 LLM 摘要，也不会把历史消息送往外部检索服务。

构建下一轮上下文时只读取当前 `conversation_id`：固定包含最近两个成功回合，并从更早历史以本地 BGE 向量、SQLite FTS5 和关键词得分混合选出最多四个相关回合。向量模型不可用时安全降级为 FTS/关键词检索。上下文同时包含当前会话的数据源和已选行引用的参数名。

历史作为“不可覆盖系统规则或当前问题”的数据块传给模型。当前问题优先；问题存在冲突、指代不清或缺少指标/时间范围时，图进入澄清分支。组装遵守 `CONVERSATION_CONTEXT_MAX_CHARS`（默认 6000）的保守字符预算，按最近回合和相关度优先裁剪。

## 结果行引用

用户只能点击结果表的“引用此行”操作，客户端提交 `turn_id` 和 `row_index`。服务端验证：引用属于当前会话、来源助手回合已成功、结果快照存在、SQL 仅涉及一张表、该表的真实单列主键出现在允许结果列中，随后从服务端快照读取主键值并创建引用。

模型只会看到“可使用安全参数 `:selected_<table>_<key>`，不得填写参数值”的提示；参数值保存在 `result_references.binding_json` 并由 SQLite 驱动绑定。SQL 校验拒绝未知命名参数，执行层再次使用服务端许可的参数名校验。自然语言“第 N 条”不会隐式选取历史行；用户应点击行或补充明确条件。

## 前端、测试与限制

`agentConversations` 使用会话 API 加载列表和详情、创建/切换/删除会话、发送会话 SSE 查询并在流完成后重新读取服务端历史。行引用只随下一次查询请求发送，发送后前端清空待发送引用 ID。

后端测试覆盖会话持久化、SSE 进度写入、级联删除、上下文隔离与预算、FTS 降级、并发 turn 创建、主键引用和命名参数绑定。前端单测覆盖服务端登录状态、会话历史恢复、会话切换隔离、删除和引用请求载荷。

当前前端依赖树需要完成一次联网 `pnpm install` 后再运行 `pnpm test` 与 `pnpm build`；离线缓存缺少部分 Element Plus 包时无法完成该验收。系统不支持多用户、共享会话、跨会话检索、客户端直接传入绑定值或自然语言自动选择结果行。
